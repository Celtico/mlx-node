The native MLX engine for Node.js.

Run large language models with Apple's MLX straight from Node.js: a Node-API addon written in C++, with generation, prompt cache and LoRA training steps on the GPU. No Python process, nothing to compile.

$npm install @celticopetit/mlx-node
View on GitHub →

What's inside

A small, focused engine that works with token ids. For chat templates and the training loop, use node-mlx-lm on top of it.

generate()

Generation

Streaming tokens, greedy or sampled with temperature, top-p and top-k. Greedy output is token-for-token identical to mlx_lm.

prompt cache

Prompt cache

Like mlx_lm's LRUPromptCache: the next turn of a conversation only processes what is new.

loadAdapters()

LoRA adapters

Loads adapters.safetensors from mlx_lm lora, or from training here. Swap them without reloading the model.

trainStep()

LoRA training steps

Forward, backward and Adam on the GPU, with optional gradient checkpointing. Losses match mlx_lm.

Small API, in plain Node.js

Load a model folder in mlx-community format and generate. Calls are synchronous and use the GPU, so run the engine in its own process (a child process or an Electron utilityProcess) and your UI never waits on it.

engine.js
const { NativeModel } = require('@celticopetit/mlx-node');

const model = new NativeModel('./MiMo-V2.6-9B-4bit');

for (const id of model.generate(promptIds, {
  maxTokens: 200, temperature: 0,
})) {
  // one token id at a time
}

console.log(model.lastPrompt);
// { reused: 812, total: 840 } from the cache

model.loadAdapters('./adapters');
model.close(); // frees the GPU memory

npm install, nothing to compile

No Xcode, no cmake, no Python on the machine that installs it.

  1. Prebuilt addon. The engine for this exact version comes from the GitHub release, built and tested by CI on an Apple Silicon runner.
  2. Official MLX. libmlx and mlx.metallib come from Apple's mlx-metal package on PyPI, at the exact MLX version the addon was built with, for your macOS.
  3. Next to the addon. Everything lands in the package's own folder and is only looked for there, so it also works inside a packaged Electron app.
